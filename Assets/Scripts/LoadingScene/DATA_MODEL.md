# 고양이 성장게임 저장 구조

- CatGameCatalog: 공통 캐릭터/장비/유물 정의. Unity Create > Cat Raising > Game Catalog로 생성한다. 기본 고양이 수치는 임시 밸런스 값이다. 공격 및 효과 ID에 대응하는 전투 코드는 아직 구현하지 않았다.
- BackendUserData: 진행도, 재화, 보유 목록, 장착 정보, 방치 보상 기준 정보. 캐릭터/유물은 종류당 하나, 장비는 개별 instanceId를 사용한다.
- BackendGameData: 기존 로그인 흐름에서 USER_DATA를 읽고, 없는 경우 기본 고양이 하나와 빈 재화/장비/유물 목록을 저장한다.

## 서버 저장 형식

기존 USER_DATA 테이블을 유지하고 schemaVersion(정수), playerDataJson(문자열) 필드를 전송한다. 서버 콘솔은 수정하지 않았다. 스키마를 지정하는 테이블이면 두 필드의 허용 여부와 기존 필수 필드를 확인해야 한다. 전체 세이브를 한 행으로 저장하므로 목록이 커지면 테이블 분리를 진행한다.

기존 데이터는 level을 accountLevel로 옮기고 전체 원본을 legacySnapshotJson에 보관한다. 이름 기반 아이템과 atk는 새 게임 스탯에 자동 적용하지 않는다. 로그인 흐름에서 기존 형식을 감지하면 GameDataUpdate로 같은 행에 새 형식을 저장한 후 로그인 완료를 처리한다. 저장 실패 시 완료를 보류하며 로그인 버튼으로 조회부터 재시도한다. 이미 새 형식이면 변환 저장을 생략한다. 기존 필드는 삭제하지 않는다.

최종 스탯 계산, 장착 검증/변경, 강화 비용 처리, 전투 효과 실행, 방치 보상 지급은 이후 구현 범위다. lastSettledUnixSeconds=0은 서버 정산 기준 미설정 상태이며 클라이언트 시각으로 보상을 지급하면 안 된다.

## Unity에서 확인할 시나리오

1. 새 계정 로그인: 기본 고양이 한 마리, 레벨 1, 재화 0, 장비/유물 없음.
2. 재로그인: 동일 행을 읽고 신규 행을 추가하지 않음.
3. 기존 테스트 계정: 계정 레벨과 원본이 보존되고 같은 행에 schemaVersion=1, playerDataJson이 추가됨. 재로그인 시 변환 저장 로그가 나오지 않음.
4. 조회 실패/잘못된 JSON/미지원 버전: 로그인 완료로 진행하거나 신규 삽입하지 않음.
5. GameDataUpdate 후 재조회: 변경한 성장/보유/장착 값이 복원됨.
6. 변환 저장 실패: 로그인 완료 이벤트가 실행되지 않고 재시도 안내가 표시됨. 다시 로그인하면 서버 상태를 새로 읽어 처리함.

Unity 실행과 서버 왕복 검증은 아직 수행하지 않았다.
