# 고양이 키우기 — 비전공자를 위한 개발 내용과 코드 구조

최종 갱신: 2026년 11월 10일
프로젝트: CatRaising  
기준: 현재 `Assets/Scripts`, `Assets/Resources`의 코드·에셋과 개발 내용. 전체 상태와 검증 범위는 [개발 현황](개발_현황.md)을 참고합니다.

이 문서는 프로그래밍을 처음 접하는 사람도 게임의 구성과 코드를 나눈 이유를 이해할 수 있도록 정리한 안내서입니다. 기능이 구현된 것과 실제 기기에서 검증이 끝난 것은 구분해서 설명합니다.

## 1. 지금까지 어떤 게임을 만들었나?

현재 게임은 **로그인해서 고양이를 키우고, 전투로 보상을 얻어 캐릭터·유물을 성장시키며, 진행 상황을 서버에 저장하는 게임**입니다.

처음에는 회원가입·로그인과 유저 데이터 저장부터 시작했습니다. 이후 다음 기능을 차례로 추가했습니다.

- 자동 공격과 자동·수동 이동이 가능한 메인 전투
- 캐릭터별 공격 방식과 공격 모션
- 공격·피격 시 효과를 주는 유물
- 캐릭터·유물 상점과 확률 뽑기
- 경험치 결정 수집, 캐릭터 레벨, 성급, 스킬 트리
- 고양이 4마리로 도전하는 레이드와 고양이 3종을 편성하는 타워 디펜스 던전
- 보스 공격 모션, 광역 공격 예고, 몬스터 소환
- 픽셀 스타일의 배경·버튼·카드·프로필
- 광고를 보고 크리스탈을 받는 흐름
- 오브젝트 풀·타일맵·프레임 공유를 이용한 성능 개선
- 저장 요청 묶기와 미저장 전투 보상 복구
- 첫 진입 튜토리얼 8종과 설정에서 안내 다시 보기
- 로딩·메인·던전·레이드별 반복 BGM, 전투·UI 효과음, 분리된 볼륨 설정

기능이 많아진 뒤에는 중복 코드를 합치고, 비슷한 역할의 파일을 폴더로 정리했습니다.

## 2. 게임을 실행하면 어떤 일이 일어날까?

```text
로딩 화면
   ↓
회원가입 또는 로그인
   ↓
뒤끝에서 내 게임 데이터 불러오기
   ↓
기기에 남은 미저장 전투 보상 확인
   ↓
게임 화면
   ├─ 메인 전투 → 골드 획득·경험치 결정 수집
   ├─ 상점·캐릭터·유물 → 구매·성장·장착
   └─ 레이드·던전 → 특수 전투와 진행
                       ↓
                  데이터 저장
```

로그인 버튼을 누르면 바로 전투 화면을 여는 것이 아닙니다.

1. 입력한 아이디와 비밀번호를 확인합니다.
2. 해당 계정의 골드, 고양이, 유물 등을 불러옵니다.
3. 이전 종료 때 저장하지 못한 전투 보상이 있는지 확인합니다.
4. 준비가 끝나면 게임 화면으로 이동합니다.

이 순서는 **내 데이터를 불러오기 전에 임시 데이터로 게임이 시작되는 문제를 막기 위한 것**입니다.

## 3. 코드 폴더 구조

주요 역할을 이해할 수 있도록 대표 파일만 표시했습니다.

```text
Assets/Scripts
│
├─ LoadingScene                       로그인 화면과 게임 진입
│  ├─ LoadingLoginUI.cs               로그인·회원가입 입력 화면
│  └─ BackendManager.cs               로그인 절차와 씬 전환
│
├─ Backend                            계정과 서버 저장
│  ├─ Authentication/BackendLogin.cs  뒤끝 로그인 처리
│  ├─ Models/BackendUserData.cs        저장할 데이터의 형태
│  └─ Storage
│     ├─ BackendGameData.cs           불러오기와 저장
│     ├─ PlayerSaveRow.cs             DB 테이블과 코드 연결
│     ├─ PlayerDataValidation.cs      데이터 기본 검사
│     ├─ LegacyGameDataReader.cs      이전 데이터 읽기
│     └─ CombatRewardJournal.cs       미저장 전투 보상 기록
│
├─ GameScene                          게임 화면의 연결과 운영
│  ├─ CatGameScene.cs                 UI·전투·저장 연결
│  ├─ Session/CatGameSession.cs        구매·강화·뽑기 등의 처리
│  └─ UI                             상점·프로필·스킬 등 화면
│
├─ Content                            공통 설정과 게임 규칙
│  ├─ Definitions                    캐릭터·유물 기본 정보
│  └─ Rules                          성장·뽑기·스킬·던전 규칙
│
├─ Combat                             실제 전투
│  ├─ CatFieldController.cs           전투 필드 구성
│  ├─ Core                           공격·피해·몬스터·경험치
│  ├─ Movement                       이동·길찾기·파티 배치
│  ├─ Visuals                        모션·이펙트·카메라
│  └─ Map                            바닥·장식·장애물
│
├─ UI/Common                          여러 화면에서 공유하는 UI
└─ Editor                             Unity 편집 작업을 돕는 도구
```

화면 담당, 게임 규칙 담당, 전투 담당, 기록 담당을 나눈 구조입니다. 상점 버튼을 예쁘게 바꿀 때 로그인 코드를 건드리지 않고, 공격력을 조정할 때 화면 전체를 고치지 않도록 구성했습니다.

## 4. 게임을 연결하는 중심 파일

`CatGameScene.cs`는 게임 화면의 연결 담당입니다. 주로 다음 세 부분을 연결합니다.

| 담당 | 역할 | 예시 |
|---|---|---|
| CatGameSceneUI | 화면 표시와 사용자 입력 | 구매 버튼을 눌렀다는 요청 |
| CatGameSession | 조건 확인과 데이터 변경 | 골드 확인, 구매 처리, 저장 실패 시 복원 |
| CatFieldController | 전투 필드 구성과 진행 | 몬스터 생성, 이동, 공격, 레이드 시작 |

고양이를 구매하는 흐름은 다음과 같습니다.

```text
구매 버튼 클릭
   ↓
UI가 구매 요청 전달
   ↓
CatGameScene이 Session에 연결
   ↓
Session이 골드와 보유 여부 확인
   ↓
골드 차감 + 고양이 추가 + 서버 저장
   ↓
결과에 맞춰 화면 갱신
```

버튼이 직접 골드를 빼도록 만들지 않은 이유는, 다른 화면에서 같은 기능을 사용하더라도 동일한 검사를 거치게 하기 위해서입니다. 중복 클릭이나 저장 중 재요청을 관리하기도 쉬워집니다.

여기서 **이벤트**는 한 기능이 다른 기능에 보내는 알림입니다. 예를 들어 “몬스터를 잡아 골드를 얻었다”는 알림을 받으면 데이터 담당은 골드를 더하고, 화면 담당은 숫자를 갱신합니다.

## 5. 공통 캐릭터 설정과 내 캐릭터 상태의 차이

고등어 고양이를 예로 들면 정보가 두 종류로 나뉩니다.

| 모두에게 같은 정보 | 플레이어마다 다른 정보 |
|---|---|
| 이름과 등급 | 보유 여부 |
| 공격 방식과 기본 능력치 | 현재 레벨과 경험치 |
| 이미지와 설명 | 성급과 조각 수 |
| 구매·뽑기 설정 | 투자한 스킬 |

공통 정보는 `Content`에, 개인 상태는 `BackendUserData`에 둡니다.

이렇게 하면 기본 공격력이나 설명을 바꿀 때 유저의 저장 데이터를 일일이 수정할 필요가 줄어듭니다. 공통 설정과 각자의 레벨·성급을 조합해 실제 능력치를 계산합니다.

화면에 보이는 이름과 별도로 `cat_knight` 같은 고유 ID를 사용하는 이유도 같습니다. 이름을 바꿔도 어떤 캐릭터를 보유했는지 연결이 유지됩니다.

## 6. 로그인 정보와 게임 데이터 저장

로그인 인증은 뒤끝 계정 기능이 담당합니다. 게임 진행 정보는 별도로 저장합니다.

`BackendUserData`의 주요 구성은 다음과 같습니다.

| 데이터 묶음 | 내용 |
|---|---|
| progress | 계정 레벨, 던전 진행, 프로필 이름·사진 |
| wallet | 골드, 다이아, 재료, 광고 보상 횟수 |
| characters | 보유 고양이, 레벨, 경험치, 성급, 조각, 스킬 |
| equipment | 보유 장비와 강화 정보 |
| relics | 보유 유물과 성장 정보 |
| loadout | 현재 선택한 고양이와 장착 유물 |
| idleReward | 방치 보상 관련 상태를 담는 구조 |

**현재 DB는 캐릭터·유물마다 별도 테이블이 있는 구조가 아닙니다.** `player_save` 테이블의 사용자 데이터 안에 항목별 JSON으로 나누어 저장합니다. JSON은 여러 정보에 이름표를 붙여 묶어놓은 형식이라고 생각하면 됩니다.

이 방식은 구매처럼 여러 값이 함께 바뀌는 상황에 편리합니다.

```text
고양이 구매 → 골드 감소 + 보유 고양이 증가 → 함께 저장
```

기존 `USER_DATA`는 이전 데이터 보존과 읽기 경로를 두었습니다. 현재 신규 저장은 뒤끝 데이터베이스 SDK를 사용합니다.

데이터가 크게 늘어나면 저장 크기와 조회 방식에 맞춰 테이블 분리를 다시 검토할 수 있습니다.

## 7. 저장과 복구가 복잡한 이유

인터넷 요청은 항상 성공하지 않습니다. 앱이 종료되거나 응답이 끊길 수도 있습니다.

- 구매·강화: 작업 시 저장을 요청하고, 일반적인 실패에서는 이전 값으로 복원합니다.
- 전투 골드·경험치: 계속 발생하므로 일정 주기로 묶어 서버에 저장합니다.
- 미저장 전투 보상: 기기에도 주기적으로 기록합니다.
- 백그라운드 전환·종료: 로컬 기록과 서버 저장을 시도합니다.

`CombatRewardJournal`은 미저장 전투 보상을 적는 메모장입니다.

```text
골드 100 획득
→ 서버에 저장 요청
→ 서버 저장 완료
→ 완료 응답을 받기 전에 앱 종료
```

다음 로그인에서 무조건 100을 다시 더하면 중복 지급됩니다. 그래서 서버의 저장 확인 표식을 읽어 이미 반영된 보상인지 확인합니다.

기기 기록은 계정별로 구분합니다. 저장 버전이 달라지거나 결과가 불확실하면 무작정 덮어쓰지 않고 확인하도록 구성했습니다.

현재 복구의 중심은 전투 골드와 고양이 경험치입니다. 모든 종류의 진행을 완벽히 복원하는 기능은 아니며, 마지막 로컬 기록 이후 갑자기 종료되면 일부 보상이 남지 않을 수 있습니다.

## 8. 전투는 어떻게 처리할까?

화면에서는 고양이가 한 번 때리는 모습이지만 내부 과정은 나뉩니다.

```text
사거리 안의 적 확인
→ 공격 대상 결정
→ 공격할 시간인지 확인
→ 피해 계산
→ 몬스터 체력 감소
→ 공격 모션과 이펙트 표시
→ 사망 시 보상 처리
```

| 코드 | 역할 |
|---|---|
| CatMovementController | 자동·수동 이동 |
| FieldNavigation | 장애물을 고려한 이동 |
| FieldCombatController | 공격 대상과 전투 진행 |
| CharacterAttack | 캐릭터별 공격 방식 |
| CombatHealth | 체력과 피해 |
| RelicEffectRunner | 유물 효과 발동 |
| CatCharacterVisual | 고양이의 방향·걷기·공격 모습 |
| FieldCombatEffects | 공격 이펙트 |
| FieldDamageNumbers | 피해·골드 숫자 연출 |

공격 그림과 실제 피해 계산을 나눈 이유는 서로 다른 작업이기 때문입니다. 망치 모션을 수정하면서 공격력 계산까지 달라지는 일을 줄일 수 있습니다.

몬스터는 생존 시간에 따라 종류와 수가 늘어납니다. 캐릭터가 죽으면 생존 시간이 초기화되어 처음부터 다시 진행합니다.

## 9. 2.5D 표현과 장식 접지

현재 방식은 바닥 위의 공간 좌표로 이동하면서 2D 그림을 카메라 방향으로 보여주는 방식입니다.

```text
바닥: 공간 위의 평면
캐릭터·몬스터·장식: 2D 그림
카메라: 위에서 비스듬히 내려다봄
```

`FieldBillboard`는 그림을 카메라 쪽으로 향하게 하고 위치에 따라 앞뒤 표시 순서를 조정합니다. 종이 인형을 바닥에 세워놓고 바라보는 것과 비슷합니다.

이때 실제 발 위치와 그림의 기준점이 맞아야 합니다. 최근 추가한 `FieldPropGrounding`은 투명 여백을 제외한 그림의 아래 끝을 찾아 돌·우물·나무·상자·화분 등의 높이를 보정합니다.

보정 코드는 연결되어 있지만 실제 장식이 모두 자연스럽게 보이는지는 Unity 화면에서 확인해야 합니다.

## 10. 레벨·성급·스킬을 나눈 이유

| 성장 방식 | 필요한 것 | 의미 |
|---|---|---|
| 레벨 | 경험치 결정 수집 | 계속 플레이하며 성장 |
| 성급 | 같은 고양이의 조각 | 중복 획득의 가치 |
| 스킬 | 레벨에 따른 스킬 포인트 | 전투 방식 선택 |

성급은 0성부터 5성까지입니다. 필요한 조각은 순서대로 **10 / 30 / 80 / 200 / 500개**입니다.

스킬은 근거리·원거리·공통으로 구분했습니다. 각 스킬을 5단계까지 투자하고 선행 스킬을 완성하면 다음으로 넘어갑니다. 같은 갈림길에서는 한쪽을 선택하며, 공통 스킬은 별도로 투자합니다. 초기화 비용은 다이아 10개입니다.

규칙을 `Content/Rules`에 모아두었기 때문에, 조각 비용이나 경험치 요구량을 바꿀 때 화면 코드를 뒤질 필요가 줄어듭니다.

## 11. 상점과 뽑기의 구조

뽑기는 세 부분으로 나눴습니다.

1. 규칙: 어떤 등급이 어느 확률로 나오는가?
2. 처리: 비용을 낼 수 있는가? 새 획득인가, 중복인가?
3. 연출: 상자가 흔들리고 카드가 나타나는 모습

상자 애니메이션은 결과를 보여주는 역할입니다. 획득 처리와 저장은 별도로 관리해 연출 중 화면을 닫거나 버튼을 여러 번 누르는 상황을 다루기 쉽게 했습니다.

캐릭터와 유물의 공통 추첨 로직은 `ContentDrawSelection`에 모았습니다. 공통 오류를 수정할 때 두 군데를 따로 고치지 않아도 됩니다.

상점 고양이 목록은 Common → Epic → Unique → Legendary 순서로 표시하고 같은 등급 안에서는 기존 순서를 유지합니다.

## 12. 메인·레이드·던전의 씬과 전투 규칙

- 메인 전투: 생존하며 몬스터를 처치하고 성장합니다.
- 레이드: 고양이 4마리를 전후열로 편성해 제한 시간 안에 보스를 처치합니다.
- 던전: 보유 고양이 3종을 편성하고, 비용을 사용해 길 밖 타일에 소환합니다. 준비 단계에서 배치를 바꾸고 웨이브를 방어합니다.

`GameScene`, `RaidScene`, `DungeonScene`으로 화면과 전투를 분리했습니다. `CatGameRuntime`이 데이터와 세션을 유지하고 `CatEncounterScene`이 던전·레이드 진입을 처리합니다. 메인·레이드는 필드 전투를 사용하고, 던전은 `DungeonDefenseBattle`과 `DefenseTileBoard`로 소환·배치·기지 방어를 처리합니다. 공통 콘텐츠 정의와 성장 규칙을 재사용합니다.

입장 전에 저장하고, 결과는 중복 처리되지 않도록 관리합니다. 메인으로 돌아오면 필드는 다시 구성되지만 저장된 재화와 성장은 유지됩니다.

레이드 보스의 광역 공격·위험 표시·몬스터 소환은 별도 파일로 나눴습니다. 파티 배치는 `RaidPartyFormation`에서 관리합니다.

## 13. UI 파일이 많은 이유

`CatGameSceneUI.Shop.cs`, `CatGameSceneUI.Profile.cs`, `CatGameSceneUI.Skills.cs` 등은 하나의 UI 클래스를 주제별로 나눠 적은 파일입니다. 이를 `partial class`라고 합니다. 책 한 권을 여러 장으로 나눈 것과 비슷합니다.

| 바꾸고 싶은 것 | 찾아볼 파일 |
|---|---|
| 상점 | CatGameSceneUI.Shop.cs |
| 프로필 | CatGameSceneUI.Profile.cs |
| 재화 표시 | CatGameSceneUI.Currency.cs |
| 캐릭터 카드 | CatGameSceneUI.CharacterCards.cs |
| 스킬 화면 | CatGameSceneUI.Skills.cs |
| 뽑기 연출 | CatGameSceneUI.Draw.cs |
| 메인 전투 UI | CatGameSceneUI.SceneLayout.cs |

파일은 나뉘어 있지만 내부 상태는 공유하므로 완전히 독립된 구조는 아닙니다. 공통 버튼 디자인·글씨·움직임은 `UI/Common`에 두었습니다.

프로필 이름과 사진 변경은 UI가 입력을 받고, 세션이 확인·저장하며, 성공 후 화면을 갱신합니다. 사진은 보유 고양이 중에서 선택합니다.

메인 전투의 안내 문구는 숨겼고, 이동 버튼은 AUTO로 표시합니다. 자동일 때는 밝은 초록색, 수동일 때는 어두운 색이지만 두 상태 모두 눌러 전환할 수 있습니다.

## 14. 렉을 줄인 방법

| 방법 | 쉬운 설명 | 줄이려는 부담 |
|---|---|---|
| 몬스터 오브젝트 풀 | 죽은 몬스터를 버리지 않고 다시 사용 | 생성·삭제 반복 |
| 바닥 타일맵 | 반복 풀 바닥을 묶어서 표시 | 수많은 개별 바닥 오브젝트 |
| 애니메이션 프레임 공유 | 같은 캐릭터의 그림 조각을 함께 사용 | 반복적인 프레임 생성 |

오브젝트 풀은 식기를 매번 새로 만드는 대신 재사용하는 것과 같습니다. 필요한 몬스터도 한꺼번에 준비하지 않고 조금씩 생성합니다.

타일맵은 현재 반복 풀 바닥에 적용되어 있습니다. 우물·나무 등 모든 장식을 타일맵으로 바꾼 것은 아닙니다.

프레임 공유는 필요한 고양이의 애니메이션만 처음에 준비하고, 이후 같은 캐릭터가 사용할 때 재사용하는 방식입니다. 각 고양이의 재생 시간과 공격 동작 상태는 따로 유지하므로 그림을 공유해도 모두 똑같이 움직이는 것은 아닙니다.

## 15. 외부 SDK와 라이브러리

| 도구 | 사용하는 곳 |
|---|---|
| 뒤끝 SDK | 계정 인증, 게임 데이터 저장 |
| DOTween | 버튼, 팝업, 뽑기, 피해 숫자 등의 움직임 |
| Google Mobile Ads | 광고 시청과 보상 흐름 |
| Unity UI·입력·타일맵 | 화면, 조작, 바닥 표시 |

SDK는 외부 서비스와 연결하는 도구 모음이고, 라이브러리는 자주 필요한 기능을 미리 만들어놓은 코드 묶음입니다. 이를 사용해 로그인 서버나 애니메이션 도구를 처음부터 만드는 일을 줄였습니다.

구글 로그인과 광고는 코드 연결만으로 서비스 검증이 끝나는 것이 아닙니다. 실제 기기 빌드와 플랫폼 설정에 맞는 확인이 필요합니다.

## 16. 편집기 도구를 따로 둔 이유

`Editor` 폴더의 코드는 게임을 하는 사람이 아니라 개발자를 위한 도구입니다.

- 실행 전에도 로그인·게임 UI를 볼 수 있도록 씬을 준비
- 맵 디자인 씬과 저장된 맵을 구성
- 그림 에셋을 가져오는 작업 보조
- 일부 플러그인 가져오기 설정 보조

게임 플레이 코드와 편집 작업 코드를 구분하면, 플레이어에게 필요 없는 편집 기능이 게임 동작에 섞이는 일을 줄일 수 있습니다.

## 17. 현재 구조의 한계와 확인할 것

핵심 플레이 흐름은 구현되어 있으며 현재는 마무리 검증 단계입니다. 특별 상점은 실제 결제가 없는 UI 시안입니다. 2026년 11월 10일 BGM·리소스 변경은 경로 정합성을 확인했지만, Unity가 초기화 중 종료되어 최신 변경의 컴파일·실제 재생 검증은 완료하지 못했습니다. 이전 검사 통과 기록은 해당 시점에만 적용합니다.

- **계정 레벨과 고양이 레벨은 별개입니다.** 고양이는 경험치로 성장하지만 프로필의 계정 경험치는 아직 본격적인 획득 흐름이 없습니다. 표시 기준은 현재 레벨 × 100입니다.
- **미리보기와 실제 로그인을 구분합니다.** 게임 씬을 단독 실행하면 서버 계정 대신 미리보기 데이터를 사용할 수 있습니다.
- **경제 규칙 상당 부분은 클라이언트에서 계산합니다.** 출시 단계에서는 뽑기·재화·광고 보상을 서버가 검증하는 구조도 검토해야 합니다.
- **데이터 구조가 있다고 모든 관련 기능이 완성된 것은 아닙니다.** 장비나 방치 보상 같은 저장 항목의 존재와 전체 콘텐츠 완성은 구분해야 합니다.
- **컴파일 성공은 실제 플레이 확인과 다릅니다.** 화면 배치, 모바일 종료 복구, 다수 몬스터 성능은 Unity와 실제 기기에서 확인해야 합니다.

## 18. 앞으로 코드를 찾을 때의 기준

| 질문 | 찾아갈 곳 |
|---|---|
| 버튼이나 팝업을 바꾸고 싶다 | GameScene/UI |
| 캐릭터 공격 모션을 바꾸고 싶다 | Combat/Visuals |
| 공격력·성장 비용·뽑기 확률을 바꾸고 싶다 | Content/Definitions, Content/Rules |
| 구매·강화 조건을 바꾸고 싶다 | GameScene/Session |
| 이동·공격·몬스터 진행을 바꾸고 싶다 | Combat |
| 로그인·저장·복구를 바꾸고 싶다 | LoadingScene, Backend |
| 맵 배치나 장식을 바꾸고 싶다 | Combat/Map, Editor/Map |

지금까지 코드를 나눈 가장 큰 이유는 **한 기능을 고칠 때 관련 없는 기능까지 함께 건드리지 않도록 하고, 같은 기능을 여러 곳에서 재사용하기 위해서**입니다.

## 19. 소리와 리소스 관리

스크립트 아래에 있던 리소스를 `Assets/Resources`로 이동하고 개별 에셋의 `.meta`를 함께 보존했습니다. 에디터의 고정 경로도 수정했으며 `Resources.Load`는 `BGM/MainBGM`처럼 Resources 아래 상대 경로를 사용합니다. 다른 위치의 기존 Resources 폴더까지 모두 합친 것은 아닙니다.

`CatBackgroundMusic`은 씬 변경에 따라 곡을 바꾸는 영속 관리자입니다. `AudioSource.loop`로 반복하며 기본 음량은 0.3입니다. 사용자 BGM 볼륨을 곱하고, 전체 AudioListener 볼륨(음소거가 아니면 0.5)을 추가 적용합니다. 기본 설정에서 최종 배율은 0.15이며, 이는 기존 대비 30%로 줄인 결과입니다.

효과음은 `CatSoundEffects`의 전투 8개·UI 4개 음원 풀을 재사용하고 `SFX/`에서 읽습니다. `CatAudioChannelSource`와 `CatLocalSettings`가 BGM·효과음 볼륨을 분리합니다. 씬별 곡과 교체 방법은 [오디오와 리소스](오디오_리소스.md)를 참고합니다.

## 20. 첫 플레이 안내와 기기 설정

메인 전투, 캐릭터, 유물, 뽑기, 레이드 편성, 던전 입장, 레이드 전투, 던전 전투의 8개 안내가 있습니다. 안내 중 전투 시간을 멈추고 닫을 때 기존 상태로 복원합니다. 완료 여부는 `progress.tutorialSeenMask`로 저장하며 설정에서 다시 볼 수 있습니다. 서버 없는 미리보기에서는 자동 안내를 표시하지 않습니다.

음량·음소거·30/60 FPS·몬스터 그림자 설정은 기기의 PlayerPrefs로 관리합니다. 계정의 성장·튜토리얼 완료 데이터와는 저장 위치가 다릅니다.
